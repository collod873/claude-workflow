so the numbers compare. Facts, no rulings. Lumaria is private: tickets are linked by number and its

## Summary

- **The run took 289 min, unpause (03:23:19) to Spec close (08:12:06), for 8 tickets.** About 73
  min was first-pass work. 169 min (58%) was rework after the first done check missed three
  sentences, and 53 min (18%) was stalls. Wave 11 stalled 44 of 70 min (63%).
- **Every sentence the first done check missed had held at an earlier wave check, then broke
  unseen.** A wave check tries only the sentences its own Wave moved, and Waves 9 to 13 moved none,
  so no check ran on the Spec from 10-07 11:48 to the done check. Sentence 1 sat broken for 58 h.
- **The fix wave was sliced without the done check's findings.** `bin/done-check` runs
  `slice --fix` with the sentence numbers alone, then posts the findings. The Slicer spent 43 turns
  re-deriving causes, filed #1025 on the wrong one, and Wave 15 (72 min) fixed what the done check
  had already named.
- **The review gate passed three of eight PRs it never judged.** When the meter reviewer writes the
  PR body while the reviewer's model answers, the reviewer reads that as the PR moving, writes
  nothing and ends green. No newer run comes. Two of the dropped verdicts were **drift**, and #1035
  merged with a money-path regression the reviewer had flagged as hollow tests.
- **Wave and done checks took 106 min of the critical path and 39% of model spend**, mostly
  because each one writes its own headless browser driver. One wave check spent 39 of 42 min
  debugging its driver on one sentence.
- **The machine moved eight times during the run** and once 55 min before it. The one before it
  (`2e6a3b4a`, the closer requiring `tickets / review`) shipped without Lumaria's caller, so #1018
  sat green 47 min for a review nothing could start, until the owner fixed the caller and updated
  the branch by hand.
- **Hooks cost nothing and refused nothing:** about 600 tool calls, zero denials, no hook over
  0.43 s. Wave 11's 120 s capture wait is gone (log upload 10 to 14 s).

## Problems

### The done check finds regressions no wave check re-tried (169 min)

| Sentence | Held at | Broke how |
| --- | --- | --- |
| 1, first invoice numbered at the configured start | Wave 2's check, 10-06 17:56 | Lumaria PR #928 (Wave 3, 47 min later) seeded issued invoices. Wave 3's check tried other sentences |
| 11, Collect offline | Wave 7's check, on a production build; it saw the dev-server reload fail and put it down to dev mode | The done check tried it on the dev server |
| 16, over-billed Job cleared by its Credit | Wave 4's check | The done check built a different scenario than Wave 4's check |

`waveCheck` tries `wave` plus the unexercised sentences of the last wave check
(`src/done-checker.ts:209`). A sentence that held is never tried again until the done check. The
rework was Waves 14 to 16, three wave checks and a second done check, 05:23 to 08:12. Wave 16 (24
min) came from a held wave check's caveat, not a miss.

### The fix wave is sliced blind (72 min, one Wave)

`fixWave` runs `spawnSync(machineBin("slice"), [issue, "--fix", ...])` and only then posts the
findings (`src/done-checker.ts:245-246`). The done check had named both causes of sentence 11, with
file and line. The Slicer, handed "1, 11, 16 did not hold", took 43 turns and $2.45 and filed #1025
on a cause the evidence contradicted (a 173-line worker hand-off). Wave 15's two one-line fixes
(#1032, #1033) fixed what was failing. The findings comment landed 6 s after the fix Wave's note.

### The review gate ends green without judging (3 of 8 PRs)

5 of 12 review runs logged "writes nothing, a newer run judges: the PR moved under it while its
model answered" (#1029's repair twice, #1033 twice, #1035 once) and ended green. In each, the meter
reviewer had written the PR body 2 to 16 s before the reviewer's re-read. `withLines`
(`src/meter-reviewer.ts:60`) appends meter lines after a blank line; `withoutMeterLines`
(`src/reviewer.ts:21`) drops the meter lines but keeps the blank lines, so the fingerprint
(`src/reviewer.ts:33`) changes and `movedUnder` (`src/reviewer.ts:262`) stands down. An App body edit
starts no run, so no newer judgement comes. Dropped verdicts: #1029's repair (match), #1033's
branch-updated head (drift), #1035 (drift: tests that stay green with their guard deleted).

#1035 then merged with a regression on the money path: any non-ok answer to a queued Collect sync,
including the generic one Lumaria's action wrapper returns for a database outage, now marks the
queued motion refused for good. It is never resent, even after a reload, and the tech's banner says
to try again forever. Before #1035 a reload resent it, and the client id kept the resend idempotent.

### Each check writes its own browser driver (106 min of checks)

No stage has a browser driver. Every done check, wave check and browser-testing builder installs
puppeteer-core or playwright-core into /tmp or writes raw CDP. Wave 15's wave check spent 39 of 42
min on its own driver for one sentence (model time 3.4 min), hitting a trap builder #1030 had
already worked through 35 min earlier. The same sentence took 6.3 min inside the first done check.
The final done check tried all 22 tryable sentences in 19.1 min.

### Jobs on the PC share Docker, /tmp and the process table

The Wave 14 wave check migrated and reset another job's Postgres container, which vanished mid-run;
Wave 16's check lost about 7 min the same way. The first done check's `pkill` killed its own shell.
Builder #1030's `kill $(pgrep -f "next dev")` matched the owner's own Next servers and was refused
only because they run as another user. Checkers write fixed paths like `/tmp/dev.log`.

### The machine moved under a running Spec

Lumaria runs used seven machine SHAs. Nine jobs in four runs ran the workflow file of one commit
and the code of a newer one, the Wave 13 slice among them: `uses: ...@main` fixes the YAML when a
run is created, while each job checks out claude-workflow `main` when it starts (`tickets.yml:28`,
every job in `specs.yml`). None failed from it.

### Lone failures, fixed where they are

- **A ticket the owner closed was built and merged.** Taking `waiting` off #1015 at 03:23:00
  started a build; the owner closed it 2 s later. `tickets.yml:56` sets `held` on `unlabeled
  waiting` with no closed-state test, and nothing re-reads the state before `building`. The builder
  wrote the gate the owner had declined and renumbered four ADRs.
- **A second hire in one job overwrites the first's transcript** (`src/stage.ts:139,142`): the end
  of Wave 13's slice and Wave 16's wave check have none.
- **Sentence 11 missed at the done check and again at the next wave check without `stuck`**:
  `waveCheck` compares only with the last wave check, never the last done check
  (`src/done-checker.ts:213`).
- **A wave check ran right before a done check that tried the same sentence** (Wave 16's, 11.9
  min).
- **Every slice prompt is about 172 KB**, carrying closed Waves' PRs, about 90 s to first answer.
- **A review `drift` turns the run red**, and Rerun by dispatch fires a rerun that stands down.
