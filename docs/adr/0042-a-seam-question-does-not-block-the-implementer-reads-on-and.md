# A seam question does not block: the implementer reads on and leaves a countable trace

An implementer that needs to read outside its brief reads on. It files no blocking question and keeps
its slice. It names each module it read in `outOfBriefReads`,
and lane 05 counts those per module on the *Out-of-brief reads by module* tracker issue.

The brief stays narrow because an implementer that reads broadly couples broadly, and nothing
downstream catches bad coupling. But the same evidence says the class barely arrives: the old seam
lens found one instance in 28 sessions. A mandatory round trip pays a certain cost every time to
prevent a rare event.

A rising count is a finding about lane 03, not lane 05: the seam manifest is wrong for that module,
a pattern one blocked implementer's issue would never accumulate.

**Rejected: blocking and re-firing lane 03's seam picker.** The right answerer, at a cost paid on
every occurrence, holding a slice across two dispatches.
