# A discovery widens a run by landing on trunk, and the trigger is the compiler rather than a count

When slice A discovers something B..N all need, A lands it on trunk. B..N absorb it on rebase or go red, and the fixer clears the red as an ordinary failure. **Nothing re-slices a run in flight**, no run pauses, no count escalates. Widening is already mechanical: A lands a commit, and `git rebase` plus the test suite decide what that means for the rest — the compiler is the trigger. A seam question does not block, but a discovery still ships, and trunk is the only channel by which one reaches a fleet.

**Rejected:** stopping the run to re-slice — it parks N implementers mid-flight and switches off the fixer; lane 03 re-slicing on a dispatch, which deletes live tickets under running implementers; an escalation count, unsupported across the 34 sibling slices measured.

**Accepted cost.** A run's width is fixed at slice time; only its content is not.
